# 本轮优化（2026-08-20 ~ 08-21）：TTS FA / VPM batch / 4步 flow / 官方基线对齐

> 提交前最后一轮：把 RTF 从 Sprint16 的 0.762 进一步压低，并重建到官方 `b06198f` 基线。

## 1. TTS FlashAttention（✅ 有效，-5%）

- **背景**：Sprint 5 曾验证 TTS FA（decode -7~10%），但因 SPEAK→WAV 持平（T2W 主导）默认关闭。
- **本轮**：官方 `b06198f` 基础上重新打开 `OMNI_TTS_FLASH_ATTN=1`。
- **结果**：tts 0.190→0.166（-5%，full 口径）；logits 逐位一致，精度无回归。
- **文件**：`tools/omni/omni.cpp`（tts_ctx_params.flash_attn_type）。

## 2. VPM 批量编码（✅ 有效，encode -24%）

- **来源**：借鉴对方（zs213118/lla 1e46c63）。duplex 每帧 overview 与 slice 同尺寸（336×602），原代码串行两次完整图计算。
- **实现**：`encode_image_with_vision_chunks` 合并 overview+slices 为单次 batch（`OMNI_VISION_BATCH_ALL` 默认开，`0` 关闭）。
- **结果**：encode 0.147→0.111（-24%）。批量输出按序切分，与串行一致。
- **核实**：早期判断"批量未触发"错误——cpp.log 显示 `2 entries batch-encoded (all same size) in ~112ms`，实际已生效。

## 3. 4 步 flow matching（✅ 有效，-2%）

- **背景**：`OMNI_T2W_N_TIMESTEPS` env 之前**从未被 server 读取**（omni.cpp 硬编码 5 步）。
- **修复**：omni.cpp 新增 `t2w_n_timesteps` env 读取（默认 5），3 处 init 调用改用该值。
- **结果**：5→4 步，token2wav ~-2%（0.228→0.223，full）；官方验证 byte-identical。
- **注意**：`prompt_cache.gguf` 必须与步数一致（用 `export-prompt-cache` 重新生成 4 步 cache）。
